## 3. Qué parámetros se repiten en los mejores cotizadores

Los cotizadores más completos no preguntan solo “qué página quieres”, sino que calculan por capas:

| Categoría                 | Parámetros comunes                                                                              |
| ------------------------- | ----------------------------------------------------------------------------------------------- |
| **Tipo de proyecto**      | Landing, web corporativa, ecommerce, app móvil, SaaS, ERP, CRM, marketplace, sistema interno    |
| **Etapa del producto**    | Idea, PoC, MVP, versión completa, rediseño, mantenimiento                                       |
| **Industria**             | Retail, salud, logística, educación, minería, inmobiliaria, finanzas, construcción              |
| **Plataformas**           | Web, móvil, escritorio, ambas, panel administrativo                                             |
| **Cantidad de usuarios**  | Menos de 10.000, 10.000–100.000, más de 100.000, usuarios internos/externos                     |
| **Complejidad funcional** | Login, roles, dashboard, reportes, inventario, pagos, notificaciones, reservas, geolocalización |
| **Diseño UX/UI**          | Sin diseño, plantilla, diseño personalizado, prototipo Figma, branding completo                 |
| **Integraciones**         | Webpay, Transbank, MercadoPago, APIs externas, ERP, CRM, WhatsApp, email, Google Maps           |
| **Infraestructura**       | Hosting compartido, VPS, cloud, Docker, CI/CD, backups, monitoreo                               |
| **Equipo requerido**      | Frontend, backend, UI/UX, QA, DevOps, PM, soporte                                               |
| **Tiempo esperado**       | Urgente, normal, flexible, fecha límite                                                         |
| **Soporte postventa**     | Sin soporte, mensual, SLA, mantención evolutiva                                                 |

## 4. Diferencia clave: cotización real vs captura de lead

La mayoría **no entrega una cotización final cerrada**. Entregan una de estas 4 cosas:

| Resultado                       | Qué significa                                                                                                                                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Precio fijo inmediato**       | Más común en páginas web simples o ecommerce básico. Ejemplo: Best Solution Chile muestra precios desde $250.000, $350.000 y $450.000 CLP con extras visibles. ([Best Solution][8])                       |
| **Rango estimado**              | Muy usado en software a medida. Ejemplo: SDH muestra rango inicial y plazo según respuestas. ([Software Development Hub][4])                                                                              |
| **Reporte técnico descargable** | Más avanzado. Vention y Leobit apuntan a resumen, rango, equipo y roadmap. ([Vention][1])                                                                                                                 |
| **Formulario a ventas**         | El usuario completa datos y un agente cotiza después. Ejemplo: Peppernode envía el costo por email dentro de 1 hora; Devint trabaja con conversación inicial y luego propuesta técnica. ([Peppernode][6]) |

## 5. Lo que yo copiaría para tu propio cotizador

Para tu caso, como tú quieres usarlo para **cotizaciones web/software con clientes**, yo haría un modelo híbrido:

**Primera pantalla:** cotización rápida con precio referencial visible.
**Segunda pantalla:** desglose avanzado por módulos.
**Tercera pantalla:** captura de datos para enviar PDF/propuesta.
**Cuarta pantalla:** botón directo a WhatsApp, correo o agendamiento.

La fórmula ideal sería:

```txt
Precio base del tipo de proyecto
+ cantidad de vistas/secciones
+ módulos funcionales
+ integraciones
+ diseño UX/UI
+ carga inicial de contenido/productos
+ infraestructura/deploy
+ documentación/capacitación
+ soporte mensual opcional
= rango estimado + valor referencial
```

Mi recomendación: **sí mostrar un valor**, pero siempre como:

```txt
Estimación referencial: desde $X hasta $Y + IVA
La cotización final se confirma después de revisar requerimientos.
```

Así das transparencia, filtras clientes curiosos y evitas quedar amarrado a un precio mal calculado.
